## Feature I picked
- Note search: a GET /search route that filters in-memory notes by a query string against title, body, and tags.

## Plan from chat
- No dict schema changes needed; title, body, tags already exist.
- New route: GET /search?q=... with optional field param (title/body/tags/all).
- Matching logic: case-insensitive substring for title/body, exact match for tags.
- UI: search bar on main page, results page reuses note card layout, echoes query back.
- Edge cases: empty q redirects to full list, no matches shows empty state not 404, special characters treated as literals.
